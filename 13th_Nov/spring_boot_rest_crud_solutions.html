Before you start

The starter projects are not identical on every machine, so this guide makes two assumptions. Adjust them if your project differs.

  • Package names. This guide uses com.example.notification (Q1), com.example.weather (Q2) and com.example.fitness (Q3). Keep the package line your starter project already has, and keep every new class in the same base package or a sub-package of it, so Spring can find it.
  • Spring Boot version. The code uses jakarta.persistence.* (Spring Boot 3). If your project uses Spring Boot 2, change those imports to javax.persistence.*. Nothing else changes.

How a REST request travels

Client (Postman / test) ──HTTP──> Controller ──> Repository ──> Database (H2) <──JSON── (decides status) (saves / finds) (stores rows)
  • Entity: a Java class that maps to a database table. One object = one row.
  • Repository: an interface Spring turns into a working class that can save, find and delete entities. You write no SQL.
  • Controller: receives HTTP requests, calls the repository and returns the HTTP status and JSON body.

AnnotationMeaning

Question 1: Bean configuration with XML, Java and annotations

Topic: Spring Application Context and beans

Part 1. Understand the question

A bean is simply an object that Spring creates and manages for you. All beans live in the Application Context, which is Spring's container. Other classes can then ask the container for a bean instead of creating it with new.

Spring lets you tell the container about beans in three different ways. This question asks you to use all three, one for each group of classes:

SNBean nameClassConstructor argumentConfigure using
1smsNotificationServiceSmsNotificationService"SMS_SERVICE"Java
2callNotificationServiceCallNotificationService"CALL_SERVICE"Java
3emailNotificationServiceEmailNotificationService"EMAIL_SERVICE"Annotation
4thirdPartyNotificationServiceThirdPartyNotificationService"THIRD_PARTY_SERVICE"XML

What the three styles mean

  • Java-based: write a class marked @Configuration with methods marked @Bean. Each method creates and returns one object.
  • XML-based: describe beans in an XML file using <bean> tags. A Java class then imports that file with @ImportResource.
  • Annotation-based: mark the bean directly in code using annotations. Here we do it in App.java, which is already a configuration class because of @SpringBootApplication.

The unit tests ask the context for each bean by name, so the names in the table must match exactly, including capital letters.

Part 3. The solution

Four files change. Work through them in order.

Step 1. Beans #1 and #2: Java-based configuration

Each @Bean method builds one object. The bean name is set with name = "...", which is what the tests look up.

src/main/java/com/example/notification/JavaBasedConfiguration.javaedit this file
package com.example.notification;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class JavaBasedConfiguration {

    @Bean(name = "smsNotificationService")
    public SmsNotificationService smsNotificationService() {
        return new SmsNotificationService("SMS_SERVICE");
    }

    @Bean(name = "callNotificationService")
    public CallNotificationService callNotificationService() {
        return new CallNotificationService("CALL_SERVICE");
    }
}

Step 2. Bean #4: XML-based configuration (two files)

First describe the bean in the XML file. id is the bean name, class is the full class name including the package, and constructor-arg supplies the constructor value.

src/main/resources/xml_based_bean_configuration.xmledit this file
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
           http://www.springframework.org/schema/beans/spring-beans.xsd">

    <bean id="thirdPartyNotificationService"
          class="com.example.notification.ThirdPartyNotificationService">
        <constructor-arg value="THIRD_PARTY_SERVICE"/>
    </bean>

</beans>

Then tell Spring to read that XML file. classpath: means "look inside src/main/resources".

@ImportResource("classpath:xml_based_bean_configuration.xml")

}

Step 3. Bean #3: annotation-based configuration in App.java

@SpringBootApplication already includes @Configuration, so a @Bean method can live directly in App.java.

src/main/java/com/example/notification/App.javaedit this file
package com.example.notification;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class App {

    public static void main(String[] args) {
        SpringApplication.run(App.class, args);
    }

    @Bean(name = "emailNotificationService")
    public EmailNotificationService emailNotificationService() {
        return new EmailNotificationService("EMAIL_SERVICE");
    }
}

Another valid way to do bean #3. You can annotate the service class itself, so no @Bean method is needed in App.java:

EmailNotificationService.java (alternative)use this OR the @Bean method above
package com.example.notification;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

@Component("emailNotificationService")
public class EmailNotificationService {

    private final String serviceName;

    public EmailNotificationService(@Value("EMAIL_SERVICE") String serviceName) {
        this.serviceName = serviceName;
    }

    public String getServiceName() {
        return serviceName;
    }
}

Use only one of the two approaches. If both exist, Spring sees two beans with the same name and the application fails to start.

How the pieces fit together

  1. Spring Boot starts from App and scans its package, finding JavaBasedConfiguration and XmlBasedConfiguration because both are marked @Configuration.
  2. JavaBasedConfiguration registers beans #1 and #2 by running its @Bean methods.
  3. XmlBasedConfiguration loads the XML file, which registers bean #4.
  4. App registers bean #3 through its own @Bean method.

A quick way to check: in a test, context.getBean("thirdPartyNotificationService", ThirdPartyNotificationService.class).getServiceName() should return "THIRD_PARTY_SERVICE". Run all tests with mvn test.

Question 2: Weather REST API

Topic: full CRUD with Spring Web and Spring Data JPA on an H2 database

Part 1. Understand the question

A travel company needs a service that stores daily temperature readings. Each reading is one JSON object:

Example weather JSONdata format
{
  "id": 1,
  "date": "1985-01-01",
  "lat": 36.1189,
  "lon": -86.6892,
  "city": "Nashville",
  "state": "Tennessee",
  "temperature": 17.3
}

You must build the endpoint /weather with four operations:

RequestWhat it doesSuccess responseFailure response
POST /weatherSaves a new record. The body has no id; the database assigns one.201 + the saved record including its id(input is always valid)
GET /weatherReturns all records, ordered by id from smallest to largest.200 + array of records
GET /weather/{id}Returns one record.200 + the record404 if the id does not exist
DELETE /weather/{id}Removes one record.204, empty body404 if the id does not exist

Build POST first. The tests for the other methods create their data by calling POST, so nothing else can pass until it works.

Files to create or edit: the entity (Weather), the repository (WeatherRepository) and the controller (WeatherController).

Part 3. The solution

Step 1. Entity: Weather.java

The entity has one field for every JSON property. Field names must match the JSON names exactly (lat, lon, city, ...), otherwise Spring cannot convert between JSON and Java. @GeneratedValue makes the database assign the next id automatically. LocalDate is converted to and from "YYYY-MM-DD" by Spring Boot.

src/main/java/com/example/weather/Weather.javaedit this file
package com.example.weather;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

import java.time.LocalDate;

@Entity
public class Weather {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    private LocalDate date;
    private Double lat;
    private Double lon;
    private String city;
    private String state;
    private Double temperature;

    public Weather() {
    }

    public Integer getId() { return id; }
    public void setId(Integer id) { this.id = id; }

    public LocalDate getDate() { return date; }
    public void setDate(LocalDate date) { this.date = date; }

    public Double getLat() { return lat; }
    public void setLat(Double lat) { this.lat = lat; }

    public Double getLon() { return lon; }
    public void setLon(Double lon) { this.lon = lon; }

    public String getCity() { return city; }
    public void setCity(String city) { this.city = city; }

    public String getState() { return state; }
    public void setState(String state) { this.state = state; }

    public Double getTemperature() { return temperature; }
    public void setTemperature(Double temperature) { this.temperature = temperature; }
}

Step 3. Controller: WeatherController.java (new file)

The controller maps each of the four requests to a method and chooses the correct status code. Read each method against the table in Part 1.

src/main/java/com/example/weather/WeatherController.javacreate this file
package com.example.weather;

import org.springframework.data.domain.Sort;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/weather")
public class WeatherController {

    private final WeatherRepository weatherRepository;

    public WeatherController(WeatherRepository weatherRepository) {
        this.weatherRepository = weatherRepository;
    }

    // POST /weather  -> 201 Created
    @PostMapping
    public ResponseEntity<Weather> create(@RequestBody Weather weather) {
        weather.setId(null);                          // let the database choose the id
        Weather saved = weatherRepository.save(weather);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

    // GET /weather  -> 200 OK, sorted by id ascending
    @GetMapping
    public ResponseEntity<List<Weather>> getAll() {
        List<Weather> all = weatherRepository.findAll(Sort.by(Sort.Direction.ASC, "id"));
        return ResponseEntity.ok(all);
    }

    // GET /weather/{id}  -> 200 OK or 404 Not Found
    @GetMapping("/{id}")
    public ResponseEntity<Weather> getById(@PathVariable Integer id) {
        return weatherRepository.findById(id)
                .map(ResponseEntity::ok)
                .orElse(ResponseEntity.notFound().build());
    }

    // DELETE /weather/{id}  -> 204 No Content or 404 Not Found
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Integer id) {
        if (!weatherRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }
        weatherRepository.deleteById(id);
        return ResponseEntity.noContent().build();
    }
}

Why it works

  • @RequestBody turns the incoming JSON into a Weather object; save() inserts it and returns the same object with its new id.
  • findById returns an Optional, which is "a box that may be empty". .map(ResponseEntity::ok) wraps a found record in a 200 response and .orElse(...) gives a 404 when the box is empty.
  • The sort in getAll guarantees ascending id order, which the tests check.

Question 3: Customer and Coach REST API

Topic: two related resources, a request object (DTO) and 404 handling

Part 1. Understand the question

A fitness app has two kinds of records. Every customer is linked to one coach, and many customers can share the same coach.

Example customer JSON (response)data format
{ "id": 1, "height": 180, "weight": 80, "coach": { "id": 1, "name": "Alex Doe" } }
Example coach JSONdata format
{ "id": 1, "name": "Alex Doe" }

Notice the difference for customers: when you send a customer you only give height, weight and coach_id, but when you receive one it contains the whole nested coach object. Because the two shapes differ, the request needs its own small class (a DTO, "data transfer object").

RequestBehaviourResponse
POST /api/coachBody: {"name": "..."}. Creates a coach.201 + created coach
GET /api/coachAll coaches, sorted by id ascending.200 + list
GET /api/coach/{id}One coach.200 + coach, or 404
POST /api/customerBody: {"height":..,"weight":..,"coach_id":..}. Creates a customer linked to that coach.201 + created customer
GET /api/customerAll customers, sorted by id ascending.200 + list
GET /api/customer/{id}One customer.200 + customer, or 404

Files to create or edit: CustomerRequest (new DTO), CoachController and CustomerController. The entities and repositories normally come with the starter project; they are shown below so you can see how everything connects.

Step 3. CustomerController.java

The only new idea is in create. The client sends only a coach_id number, so the controller must look up the real Coach object, attach it to the customer and then save. If that coach does not exist, the request is invalid and the method answers 400 without saving anything.

src/main/java/com/example/fitness/CustomerController.javaedit this file
package com.example.fitness;

import org.springframework.data.domain.Sort;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Optional;

@RestController
@RequestMapping("/api/customer")
public class CustomerController {

    private final CustomerRepository customerRepository;
    private final CoachRepository coachRepository;

    public CustomerController(CustomerRepository customerRepository,
                              CoachRepository coachRepository) {
        this.customerRepository = customerRepository;
        this.coachRepository = coachRepository;
    }

    // POST /api/customer -> 201 Created (400 if coach_id is missing or unknown)
    @PostMapping
    public ResponseEntity<Customer> create(@RequestBody CustomerRequest request) {
        if (request.getCoachId() == null) {
            return ResponseEntity.badRequest().build();
        }
        Optional<Coach> coach = coachRepository.findById(request.getCoachId());
        if (coach.isEmpty()) {
            return ResponseEntity.badRequest().build();
        }

        Customer customer = new Customer();
        customer.setHeight(request.getHeight());
        customer.setWeight(request.getWeight());
        customer.setCoach(coach.get());

        Customer saved = customerRepository.save(customer);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

    // GET /api/customer -> 200 OK, sorted by id ascending
    @GetMapping
    public ResponseEntity<List<Customer>> getAll() {
        return ResponseEntity.ok(customerRepository.findAll(Sort.by(Sort.Direction.ASC, "id")));
    }

    // GET /api/customer/{id} -> 200 OK or 404 Not Found
    @GetMapping("/{id}")
    public ResponseEntity<Customer> getById(@PathVariable Long id) {
        return customerRepository.findById(id)
                .map(ResponseEntity::ok)
                .orElse(ResponseEntity.notFound().build());
    }
}

Why it works

  • The response contains the nested coach object because the Customer entity holds a Coach; the request uses CustomerRequest so the client can send just coach_id.
  • Both controllers receive their repositories through the constructor. Spring supplies them automatically (this is called dependency injection).
  • The choice of 400 for an unknown coach_id is deliberate: the URL itself is fine, but the data inside the request is not. A 404 is reserved for "the id in the URL does not exist".

Common mistakes and how to test

Mistakes to look for when a test fails

SymptomLikely cause
NoSuchBeanDefinitionException (Q1)The bean name differs from the one in the table, or the XML file is not loaded with @ImportResource.
Application fails to start with "bean already defined" (Q1)Bean #3 was defined twice (both @Component and @Bean).
404 on every requestMissing @RestController, wrong @RequestMapping path, or the class is outside the main class's package.
POST returns 200 instead of 201Returned the object directly. Use ResponseEntity.status(HttpStatus.CREATED).
Fields come back nullMissing getters/setters, or the field name does not match the JSON key.
Delete of a missing id returns 204 (Q2)Check existsById before deleting, as in the solution.
Lists come back in the wrong orderUse findAll(Sort.by(Sort.Direction.ASC, "id")), not plain findAll().
package jakarta.persistence does not existYour project is Spring Boot 2. Use javax.persistence instead.
