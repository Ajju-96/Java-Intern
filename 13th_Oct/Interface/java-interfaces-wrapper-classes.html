Part 1: Interfaces

1. What an interface is

An interface is a contract. It lists what a class can do (method signatures) without saying how. Any class that implements the interface promises to provide those methods. Code that depends on the interface does not care which class is behind it, which is what makes programs easy to extend and test.

Real-life picture: a power socket. The socket (interface) defines the shape of the plug. A lamp, a phone charger and a laptop can all plug in because each one follows the same contract.

interface Payment {
    void pay(double amount);      // implicitly public abstract
}

class UpiPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid " + amount + " via UPI");
    }
}

class CardPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid " + amount + " by card");
    }
}

public class Main {
    public static void main(String[] args) {
        Payment p = new UpiPayment();   // reference type = interface
        p.pay(499.0);
        p = new CardPayment();            // swap behaviour, caller unchanged
        p.pay(499.0);
    }
}

This is runtime polymorphism: the method that runs depends on the actual object, not on the variable's declared type.

2. Syntax and rules

  • Methods are public abstract by default, even if you do not write the keywords.
  • Variables are public static final by default, so they are constants and must be initialised.
  • An interface cannot be instantiated: new Payment() is a compile error (except via an anonymous class or lambda).
  • An interface has no constructors.
  • A class uses implements; an interface extends another interface with extends.
  • A non-abstract class must implement every abstract method, and the implementation must be public. Weakening access is an error.
  • An abstract class may implement only some methods and leave the rest to its subclasses.
interface Shape {
    double PI = 3.14159;           // public static final
    double area();
}
class Circle implements Shape {
    double r;
    Circle(double r) { this.r = r; }
    public double area() { return PI * r * r; }   // must be public
}

3. Multiple inheritance through interfaces

A Java class can extend only one class, but it can implement many interfaces. This gives you multiple inheritance of type without the ambiguity problems of multiple inheritance of state.

interface Flyable  { void fly(); }
interface Swimmable { void swim(); }

class Duck implements Flyable, Swimmable {
    public void fly()  { System.out.println("Duck flies"); }
    public void swim() { System.out.println("Duck swims"); }
}

If two interfaces give a class the same default method, the compiler forces you to resolve it (see next section).

4. default, static and private methods (Java 8 and 9)

Before Java 8, adding a method to an interface broke every class that implemented it. Java 8 added default methods so interfaces can evolve safely, and static methods for helpers. Java 9 added private methods so default methods can share code.

interface Logger {
    void log(String msg);                          // abstract

    default void warn(String msg) { log("WARN: " + msg); }   // inherited by implementers

    static Logger console() {                      // called as Logger.console()
        return m -> System.out.println(m);
    }
}

interface A { default void hi() { System.out.println("A"); } }
interface B { default void hi() { System.out.println("B"); } }
class C implements A, B {
    public void hi() { A.super.hi(); }       // diamond problem: you must choose
}
Remember
Static interface methods are not inherited. Call them through the interface name, never through an object.

5. Functional interfaces, lambdas and marker interfaces

A functional interface has exactly one abstract method. A lambda expression is a short way to supply that one method. The optional @FunctionalInterface annotation makes the compiler check the rule.

@FunctionalInterface
interface Operation { int apply(int a, int b); }

public class Calc {
    public static void main(String[] args) {
        Operation add = (a, b) -> a + b;
        Operation mul = (a, b) -> a * b;
        System.out.println(add.apply(3, 4));   // 7
        System.out.println(mul.apply(3, 4));   // 12
    }
}

Built-in ones you should know: Runnable, Comparator<T>, Predicate<T>, Function<T,R>, Consumer<T>, Supplier<T>.

A marker interface has no methods at all. It simply tags a class so the JVM or a library treats it specially. Examples: Serializable, Cloneable.

Practice: Interfaces

  1. Write an interface Vehicle with start() and stop(). Implement it in Car and Bike, then call both through a Vehicle[] array.
    Answer
    Vehicle[] vs = { new Car(), new Bike() };
for (Vehicle v : vs) { v.start(); v.stop(); }
  2. Will this compile? interface X { int n; }
    AnswerNo. Interface fields are implicitly final, so n must be initialised: int n = 5;.
  3. A class implements an interface method without the public keyword. What happens?
    AnswerCompile error. The interface method is public, and an implementation cannot reduce visibility.
  4. Class C implements interfaces A and B, both with a default method hi(). What must C do?
    AnswerOverride hi(). Inside it, pick one with A.super.hi() or B.super.hi(), or write new behaviour.
  5. Write a lambda for a Predicate<String> that checks whether a string is empty.
    AnswerPredicate<String> isEmpty = s -> s.isEmpty();
  6. Interview: when would you choose an abstract class over an interface?
    AnswerWhen subclasses are closely related and need shared instance fields, constructors or partially implemented behaviour. Choose an interface when you only need to define a capability that unrelated classes can adopt.

Part 2: Wrapper Classes

1. What wrapper classes are

Java has 8 primitive types (int, double, and so on). They are fast but are not objects. Each has a matching class in java.lang that wraps the value inside an object.

PrimitiveWrapperPrimitiveWrapper
byteBytelongLong
shortShortfloatFloat
intIntegerdoubleDouble
charCharacterbooleanBoolean

You need them because:

  • Collections and generics only hold objects: List<int> is illegal, List<Integer> is fine.
  • A wrapper can be null, which lets you represent "no value" (a missing age, for example).
  • Wrappers carry helpful methods: parsing, comparing, converting, and constants such as Integer.MAX_VALUE.

Wrapper objects are immutable: once created, the value inside never changes.

List<Integer> marks = new ArrayList<>();
marks.add(85);                       // int is auto-converted to Integer
marks.add(92);
int first = marks.get(0);          // Integer is auto-converted back to int

2. Boxing and unboxing

Boxing converts a primitive to its wrapper. Unboxing does the reverse. Since Java 5 the compiler does both automatically (autoboxing).

int a = 10;
Integer b = a;                       // autoboxing  -> Integer.valueOf(a)
int c = b;                           // auto-unboxing -> b.intValue()

Integer x = Integer.valueOf(50);     // manual boxing (preferred)
int y = x.intValue();               // manual unboxing
// new Integer(50) is deprecated: use valueOf
Common bug: NullPointerException
Unboxing a null wrapper crashes at runtime.
Integer age = null;
int n = age;      // NullPointerException

Autoboxing inside a loop also creates many throwaway objects, which slows hot code:

Long sum = 0L;                       // slow: boxes on every iteration
for (int i = 0; i < 1_000_000; i++) sum += i;   // use long sum instead

3. Useful methods

// String to number (parsing)
int n = Integer.parseInt("123");
double d = Double.parseDouble("3.14");
// Integer.parseInt("abc") throws NumberFormatException

// Number to String
String s1 = Integer.toString(255);
String bin = Integer.toBinaryString(10);     // "1010"
String hex = Integer.toHexString(255);       // "ff"

// Comparing and limits
Integer.compare(3, 7);                       // negative number (3 < 7)
Integer.MAX_VALUE;  Integer.MIN_VALUE;       // 2147483647, -2147483648
Integer.sum(4, 5);  Math.max(4, 5);

// Character helpers
Character.isDigit('7');  Character.isLetter('a');
Character.toUpperCase('a');          // 'A'

// Converting between types through the wrapper
Integer num = 42;
num.doubleValue();                           // 42.0
num.equals(42);                              // true

valueOf returns a wrapper object; parseXxx returns a primitive. Both accept a String.

4. The Integer cache trap (a favourite interview question)

Integer.valueOf reuses cached objects for values from -128 to 127. Outside that range, each boxing creates a new object. So ==, which compares object references, gives surprising answers.

Integer a = 100, b = 100;
System.out.println(a == b);        // true  (same cached object)

Integer c = 1000, d = 1000;
System.out.println(c == d);        // false (two different objects)
System.out.println(c.equals(d));   // true  (compares values)
Rule
Compare wrapper objects with .equals(), never ==. Use == only when at least one side is a primitive, because then the wrapper is unboxed first.

Practice: Wrapper classes

  1. What is the output?
    Integer p = 127, q = 127, r = 128, s = 128;
System.out.println((p == q) + " " + (r == s));
    Answertrue false. 127 is inside the cache range; 128 is not, so r and s are different objects.
  2. Why does List<int> list; not compile, and what is the fix?
    AnswerGenerics accept only reference types. Use List<Integer>; autoboxing handles the conversion.
  3. What happens here?
    Integer n = null;
if (n == 0) { }
    AnswerNullPointerException. n is unboxed to compare with the primitive 0, and a null cannot be unboxed.
  4. Read a number from the string "2024" and print it plus 1.
    Answerint y = Integer.parseInt("2024"); System.out.println(y + 1); prints 2025.
  5. Does Integer x = 5; x++; modify the original object?
    AnswerNo. Wrappers are immutable. x++ unboxes, adds 1, boxes the result into a different object, and assigns it to x.
  6. Interview: what is the difference between Integer.parseInt() and Integer.valueOf()?
    AnswerparseInt returns a primitive int. valueOf returns an Integer object and uses the cache for small values.

Quick summary

  • An interface defines what a class can do; implementing classes decide how. It gives polymorphism and multiple inheritance of type.
  • Since Java 8, interfaces may have default and static methods; one abstract method makes it a functional interface usable with lambdas.
  • Wrapper classes turn primitives into immutable objects so they work with collections, generics and null.
  • Autoboxing is convenient, but watch for null unboxing, loop slowness and the == cache trap.
